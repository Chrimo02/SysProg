# Subsystem: Local features

The offline features that respond without the network: the kitchen timer,
volume management, and canned-audio playback. Files: [local/](../../main/local/).

## Kitchen timer — timer.c

[timer.c](../../main/local/timer.c). A single one-shot `esp_timer`. The clever
bit: the **remaining time is computed from a stored deadline**, so the 1 Hz
status-bar countdown needs no dedicated tick task — it just calls
`kitchen_timer_remaining_s()` each LVGL frame.

- `s_deadline_us` is an atomic (`0` = no timer), so it's safe to read/write from
  any task — the cloud `set_timer` tool calls `kitchen_timer_start()` directly
  from `network_task`.
- On expiry, `timer_done()` enqueues two canned sounds (`CANNED_TIMER_DONE` then
  `CANNED_ALARM`) and fires the done callback (→ "Timer done!" bubble via a
  flag).
- `kitchen_timer_start()` stops any running timer first; `_cancel()` returns
  whether a timer was actually running (drives "Timer cancelled" vs. "No timer
  running").

## Volume — volume.c

[volume.c](../../main/local/volume.c). Percent (0–100) mapped linearly to the
Q15 gain consumed by [audio_out](drivers.md):
`gain = AUDIO_OUT_GAIN_UNITY * percent / 100`.

- `s_percent` and `s_before_mute` are atomics → safe from any task (LVGL slider,
  local command, cloud tool).
- `volume_set` clamps to 0–100; `volume_adjust(delta)` is relative;
  `volume_mute`/`volume_unmute` remember the pre-mute level.
- Local voice commands move in 20 % steps (`VOLUME_STEP`); the touch slider and
  the cloud `set_volume` tool allow any value.

## Canned audio — canned_audio.c

[canned_audio.c](../../main/local/canned_audio.c). One **player task**
(`audio_out`, Core 1, prio 5) drives the speaker for *both* pre-recorded WAVs
(from the SPIFFS `storage` partition) **and** raw TTS PCM (local Piper or the
Gemini fallback) — over the same queue. This unification is deliberate: one I2S
writer, so "stop" aborts both,
and the timer alarm and a spoken reply serialize naturally instead of fighting
over the amp.

- **Queue item** is either a SPIFFS filename (`pcm == NULL`) or a raw PCM buffer
  (`pcm` set). The PCM buffer belongs to the caller and must stay valid until
  playback ends — which is why `canned_audio_play_pcm()` **blocks** on a
  done-semaphore.
- **`canned_audio_play(name)`** (fire-and-forget, used by local commands and
  error/UI cues) just enqueues; if the depth-4 queue is full it drops with a
  warning.
- **`canned_audio_play_pcm(pcm, samples, rate)`** (used by `speak_reply`)
  enqueues and waits, with a timeout = playback duration + 30 s slack. A guard
  (`s_pcm_waiting`) ensures a `stop()` with no waiting caller doesn't leave a
  stale token.
- **`canned_audio_stop()`** resets the queue, sets the stop flag (which breaks
  the playback loops), and wakes any waiting PCM caller.
- **WAV parsing walks RIFF chunks** rather than skipping a fixed 44 bytes,
  because the macOS `say`/`afconvert` fallback inserts an `FLLR` padding chunk
  before `data`. Only PCM/16-bit/mono is accepted.
- **Sample-rate switching**: `play_file`/`play_pcm` call `audio_out_set_rate()`
  (16 kHz canned; TTS rate comes from the source — ~22 kHz from the local WAV
  header, 24 kHz from Gemini) before streaming in 4 KB chunks. PCM is copied
  into a chunk buffer first because the gain is applied in place.

### The canned files

15 WAVs are expected (`EXPECTED_FILES`), generated by
[scripts/generate_canned_tts.py](../../scripts/generate_canned_tts.py) into
[spiffs/](../../spiffs/): timer-set confirmations (30 s … 30 min), cancelled,
done, no-timer, time-left, volume-changed, muted, unmuted, plus synthetic
`tts_alarm.wav` and `tts_error.wav` (beep patterns, no TTS). Missing files are
**not** a boot failure — that command just stays silent. The filenames are the
contract between the script and the firmware (`canned_audio.h`); change both
sides together. See [05-build-and-setup.md](../05-build-and-setup.md) for
regenerating them.

## Design notes & gotchas

- **One player, one queue, blocking PCM** is what makes "stop" and
  alarm-vs-speech serialization simple — no separate TTS queue (the spec
  proposed one).
- Variable values can't be spoken by fixed phrases — e.g. "time left" plays a
  generic "the remaining time is on the display" and the exact value shows in
  the bubble/status bar. Real spoken values need cloud TTS.
- Everything here is callable from the network task because the timer/volume
  state is atomic and `canned_audio_play` only enqueues — which is exactly what
  the cloud tool-calls rely on.
